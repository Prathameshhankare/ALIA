How to audit Aruba licenses with HPE GreenLake and Aruba Central

Technical guide • ALIA v3.1.0 • Updated October 1, 2026

The problem

Aruba environments can have inventory, licensing and monitoring information represented in different systems. A device can be visible in HPE GreenLake but absent from Aruba Central, licensed but not monitored, or present in Central without corresponding GreenLake licensing information.

Checking these conditions manually becomes repetitive as the device population grows. The useful output is not just three lists; it is a device-level reconciliation that explains what is different.

What ALIA combines

  • HPE GreenLake — device inventory and licensing information.
  • Aruba Central inventory — the device population visible in Central.
  • Aruba Central monitored devices — the devices represented in the monitored-device dataset.

How device matching works

ALIA builds a reconciliation dataset by matching devices primarily on serial number and secondarily on MAC address. The resulting record contains the GreenLake data, Central presence, monitoring state and audit classification together.

GreenLake inventory + licensing ↓ Aruba Central inventory ↓ Aruba Central monitoring state ↓ Normalize + match ↓ Device-level audit result

What the audit can identify

  • Licensed devices.
  • Devices without GreenLake license information.
  • Expired licenses.
  • Licensed devices not present in Aruba Central.
  • Licensed devices not present in Central monitored-device data.
  • Central inventory devices that are not monitored.
  • GreenLake-unlicensed devices that appear in monitored data.
  • Other reconciliation mismatches implemented by the audit engine.

Why the dashboard matters

ALIA turns the reconciliation dataset into an operational dashboard with GreenLake inventory, Central inventory, Central monitored, licensed devices, exceptions, expired licenses, audit health and coverage. The KPI cards are navigation points into more focused views rather than static reporting widgets.

Investigating a device

The audit grid is designed for investigation. You can sort by columns, right-click column headers for filtering, use the global search, and select a row to populate the Device Details pane with the combined GreenLake, Aruba Central, monitoring and audit state.

Export and audit history

Export follows the current audit view, so filters and search context are preserved. Audit history is stored locally under %LOCALAPPDATA%\ALIA\audit-history.json and is therefore available again when ALIA is reopened for the same Windows user.

Deployment

ALIA v3.1 targets Windows PowerShell 5.1 and Windows Forms. The repository contains the canonical PowerShell application and a builder that packages the application as a Windows EXE using PS2EXE.
